# Структура HTML-отчёта

`scripts/render_report.py` собирает один самодостаточный HTML (печать A4). Порядок разделов:

1. Шапка: период, путь (A/B), опорный CPA и его источник. Живые группы есть, а расход за период 0 ₽
   (`zero_spend` в `dataset.json`) — сразу под шапкой крупная плашка: «Расход кабинета за период 0 ₽», только если
   это подтвердила предполётка (`account_spent` 0); кабинет тратил — «Живые группы за период не откручивали; X ₽
   пришлось на удалённые группы» (только если удалённые группы есть и статистика остальных полная, иначе «Расход
   кабинета за период X ₽, у живых групп 0 ₽ — разложить разницу по группам не удалось»); расход кабинета неизвестен —
   «Расход живых групп за период 0 ₽». Быстрый анализ при том же 0 ₽ пишет «Кабинет за период не откручивал (0 ₽)»
   или «Живые группы за период не откручивали (0 ₽)» вместо «статистика ещё не пришла».
2. Плитки KPI: расход, показы, клики, конверсии, CPA, CTR. Есть Метрика — строка «Метрика, весь трафик VK»
   (визиты, отказы, достижения целей из `metrika_total`).
3. Чек-лист аудита по блокам A–G (`findings.json` → `checklist`): таблица «id · проверка · ✅ / ❌ / — · коротко
   почему», в заголовке блока — балл «n / m», в заголовке раздела — общий «Σn / Σm» (нет живых групп — вместо него
   «кабинет не откручивает: нет живых групп»). Под чек-листом — справочная строка о статусах ОРД (`or_status`), если
   они пришли.
   ✅ — пройдена, ❌ — не пройдена, **—** — «не проверено» (данных нет) или «нечего проверять», ❓ — «уточнить у
   клиента» (воронка подписки / лид-формы / Senler не используется, вопрос — в разделе «Вопросы к клиенту»),
   🟢 — клиент подтвердил потенциал роста воронки. Строки «—», ❓ и 🟢 не входят в знаменатель балла; в «Ограничения»
   из них попадает только «данных нет» (`unknown`). Статусы — `references/diagnostic-rules.md`, «Статусы чек-листа».
4. Находки по уровням: 🔴 срезать слив → 🟠 починить → 🟢 масштабировать → ⚪ гигиена; внутри — по эффекту ₽.
   Карточка: что, объект, надёжность, ссылка на проверку чек-листа (`check`), доказательство (числа), эффект,
   действие. 🟢-находка «Потенциал роста: <воронка>» (`funnel_potential`) появляется после ответа клиента
   «потенциал» (шаг 6 «Гейт»). Если в находку записан `client_note` (шаг 6 «Гейт»), карточка серая, с пометкой «Объяснено клиентом:
   <текст>».
5. Вопросы к клиенту (`findings.json` → `questions`; список и условия пометки —
   `references/client-questions.md`). Вопросы с пометкой «важно для вашего кабинета» идут первыми, с причиной.
6. Структура: живые группы по расходу, с режимом ставки («автостратегия», «ручная ставка»).
7. Ограничения — обязательный раздел (`references/limitations.md`), включая строки «Не проверено «…»: …» по
   каждой проверке со статусом «unknown».

Чек-лист и находки — разные вещи: чек-лист отвечает «настроено ли», находки — «сколько это стоит и что делать».
Не каждая ❌ даёт находку (например, «не тестировались форматы» — только ❌ в чек-листе).

Сводка в чат после отчёта — 5–10 строк: общий балл, итог, топ-3 находки, ссылка на файл.
