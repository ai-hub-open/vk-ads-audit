# Структура HTML-отчёта

`scripts/render_report.py` собирает один самодостаточный HTML (печать A4). Порядок разделов:

1. Шапка: период, путь (A/B), опорный CPA и его источник.
2. Плитки KPI: расход, показы, клики, конверсии, CPA, CTR. Есть Метрика — строка «Метрика, весь трафик VK»
   (визиты, отказы, достижения целей из `metrika_total`).
3. Чек-лист аудита по блокам A–G (`findings.json` → `checklist`): таблица «id · проверка · ✅ / ❌ / — · коротко
   почему», в заголовке блока — балл «n / m», в заголовке раздела — общий «Σn / Σm».
   ✅ — пройдена, ❌ — не пройдена, **—** — «не проверено» (данных нет) или «нечего проверять». Строки «—» не входят
   в знаменатель балла; «данных нет» (`unknown`) дополнительно попадает в «Ограничения». Статусы —
   `references/diagnostic-rules.md`, «Статусы чек-листа».
4. Находки по уровням: 🔴 срезать слив → 🟠 починить → 🟢 масштабировать → ⚪ гигиена; внутри — по эффекту ₽.
   Карточка: что, объект, надёжность, ссылка на проверку чек-листа (`check`), доказательство (числа), эффект,
   действие. Если в находку записан `client_note` (шаг 6 «Гейт»), карточка серая, с пометкой «Объяснено клиентом:
   <текст>».
5. Вопросы к клиенту (`findings.json` → `questions`; список и условия пометки —
   `references/client-questions.md`). Вопросы с пометкой «важно для вашего кабинета» идут первыми, с причиной.
6. Структура: живые группы по расходу.
7. Ограничения — обязательный раздел (`references/limitations.md`), включая строки «Не проверено «…»: …» по
   каждой проверке со статусом «unknown».

Чек-лист и находки — разные вещи: чек-лист отвечает «настроено ли», находки — «сколько это стоит и что делать».
Не каждая ❌ даёт находку (например, «не тестировались форматы» — только ❌ в чек-листе).

Сводка в чат после отчёта — 5–10 строк: общий балл, итог, топ-3 находки, ссылка на файл.
