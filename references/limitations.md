# Ограничения аудита

## Всегда (в каждом отчёте, дословно — `ALWAYS_LIMITATIONS` в `scripts/render_report.py`)

- В API нет разрезов по полу, возрасту, гео, площадкам и устройствам — «кто конвертит» по ним не определить.
- API не показывает, срабатывает ли пиксель: ноль конверсий может означать сломанный пиксель.
- Атрибуция (post-click или post-view) меняет число конверсий — сверяйте с настройкой кабинета.
- Данные за сегодня неполные — период заканчивается вчерашним днём.
- Статусы ОРД видны частично.

## По прогону (добавляет `limitations` в `scripts/render_report.py`)

- Данные собраны через модель (путь A): объявления разобраны только у групп с наибольшим расходом.
- Объявления не собирались — выводы на уровне групп.
- Метрика не подключена: поведение на сайте после клика не проверялось.
- Метрика без UTM-разметки: склейка только на уровне всего трафика VK, правила по группам не применялись.
- Заметки нормализации (`notes` в `dataset.json`), каждая отдельной строкой:
  - «Объявления не собраны для N групп — по ним выводы на уровне группы.»
  - «Статистика не получена для N групп — итоги и выводы по ним неполные.»
  - «Сумма по объявлениям меньше расхода группы N (часть объявлений удалена?)».
  - «Конверсии части статистики взяты из всех целей пикселя: показатель «Результат» VK не пришёл — конверсии и CPA по
    таким строкам могут быть завышены.» — старый ответ без блока `vk` (конверсии — `base.vk.result`, см.
    `references/diagnostic-rules.md`).
- Частота и охват за период не определены для N групп: VK не отдаёт охват за период (сводка — только за всё время жизни
  группы) — правила по частоте (выгорание) по ним не применялись. Сюда же — группы, у которых VK отдал охват 0 при
  показах (`uniques.reach` 0, третий живой прогон): частоту из `uniques.frequency`, `total`, `increment` не берём.
- Нет доступа к базам клиентов: проверки, зависящие от баз (C14), не выполнялись — не хватает прав у подключения
  («не проверено: нет прав»). Распознаётся по ответу `vk_ads_users_lists_list` с `code: zero_quota` при любом
  HTTP-статусе (живой прогон MCP 0.12.0 — 403) или 429 с лимитом 0.
- MCP не возвращает размер сегментов и связи с базами клиентов — размер LAL-сегментов (C13) и обновление баз (C14) не
  проверялись.
- Не удалось получить <что>: <причина> — по одной строке на каждый неудачный вызов из `collect_log.json`; «что» —
  русское название вызова («список пикселей», «статистику по дням»; `TOOL_LABELS` в `scripts/render_report.py`),
  причина — кратко «ошибка VK 504 (upstream_timeout)», без сырого JSON.
  Сбой, после которого тот же вызов (инструмент и аргументы) прошёл — позже в журнале или файлом в `raw/`, —
  не показывается (`recovered`, `mark_recovered` в `scripts/raw_store.py`).
- Расширенные поля не приняты сервером — часть проверок (маркировка, UTM, кнопки) не проверена — одна строка, если
  расширенный список `fields` был отвергнут и сработал повтор с базовым; сами упавшие расширенные вызовы
  (`superseded` в `collect_log.json`) отдельными строками не показываются.
- Авто-UTM у N групп не подтверждена API — проверьте в кабинете. — если у активных групп нет ни `enable_utm`, ни шаблона `utm`,
  а у их активных объявлений на сайт нет `utm_` в ссылке (строка «Не проверено «UTM-метки…»» тогда не дублируется).
- Статистика за период не собрана — выводы по расходу и результату недоступны.
- Пиксели кабинета не проверялись.
- Сбор прерван: `<причина>` — если в `collect_log.json` есть `aborted`.
- Не проверено «<проверка>»: <причина> — по одной строке на каждую проверку чек-листа со статусом «unknown» (данных нет:
  поле не пришло из API, путь A, нет Метрики, объявления собраны не по всем группам). Проверки «na» («нечего
  проверять») в ограничения не попадают.
