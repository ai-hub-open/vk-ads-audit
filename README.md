# vk-ads-audit

Скилл Claude для аудита и быстрого анализа кабинета [VK Рекламы](https://ads.vk.ru) **только на чтение** через
MCP-коннектор `vk-ads`, опционально с Яндекс Метрикой. Скилл ничего не меняет в кабинете: создание и правка кампаний —
[vk-ads-manager](https://github.com/ai-hub-open/vk-ads-manager), находки аудита сформулированы как действия для него.

Версия — в [VERSION](VERSION), изменения — в [CHANGELOG.md](CHANGELOG.md). До 1.0 состав правил может меняться.

## Что умеет

**Глубокий аудит** — разовая диагностика за период (по умолчанию 30 последних полных дней) → HTML-отчёт
`АУДИТ_<slug>.html`:

- чек-лист «настроено ли» по семи блокам с баллами: A — техническая настройка, B — структура, C — таргетинг,
  D — бюджет и стратегия, E — объявления, F — эффективность, G — воронка после клика (Метрика);
- находки «сколько стоит и что делать» по приоритету: 🔴 срезать слив → 🟠 починить → 🟢 масштабировать → ⚪ гигиена.
  Слив без конверсий, CPA выше цели, низкий CTR, выгорание креативов, голодание автостратегий, пустые группы,
  отклонённые объявления, дубли таргетингов, пиксель, лидеры для масштабирования;
- вопросы к клиенту (воронки подписки, лид-формы, Senler) и раздел «Ограничения» — что не удалось проверить и почему.

**Быстрый анализ** — сводка за вчера или неделю: 5–10 строк в чат, только аномалии.

Примеры запросов: «аудит VK», «разбери кабинет VK», «почему дорогой лид в VK», «что отключить в VK»,
«как у нас в VK», «сводка VK за вчера».

## Принципы

- **Только чтение.** Скрипты ходят в MCP через белый список инструментов чтения
  ([scripts/mcp_client.py](scripts/mcp_client.py)); модель на пути A тоже вызывает только `*_list`, `*_get`,
  `vk_ads_statistics_*`.
- **Модель не считает.** Все числа — из `dataset.json` и `findings.json`, их считают скрипты; модель выбирает маршрут,
  задаёт вопросы и пишет выводы словами.
- **«Не получено» ≠ «плохо».** Поле, которое API не отдал, даёт проверке статус «нет данных», а не ❌.
- **Конверсии — «Результат» VK** (`base.vk.result`) по цели оптимизации, как колонка «Результат» в кабинете;
  опорный CPA — целевой клиента или медиана живых групп той же цели.

## Установка

- **Claude Code** — маркетплейс плагинов `ai-hub-open` через `/plugin`, плагин `vk-ads-audit`.
  Обновление: `/plugin marketplace update ai-hub-open` и перезапуск.
- **claude.ai и Claude Desktop** — архив `vk-ads-audit.skill` из
  [релизов](https://github.com/ai-hub-open/vk-ads-audit/releases/latest).

Скилл сам раз за разговор сверяет свою версию с `main` и предлагает обновиться, если вышла новая.

## Что нужно

- Подключённый MCP-коннектор `vk-ads` с доступом к кабинету.
- Среда с запуском Python 3 — вся арифметика в скриптах, без неё скилл не работает. Зависимостей нет, только
  стандартная библиотека.
- По желанию — коннектор Яндекс Метрики: тогда проверяется поведение на сайте после клика (блок G).

## Как работает

Два пути сбора данных:

- **Путь A** — модель сама вызывает инструменты MCP и кладёт ответы в `raw/` рабочей папки. Так всегда в claude.ai и
  Claude Desktop. Объявления разбираются у пяти групп с наибольшим расходом, отчёт это оговаривает.
- **Путь B** — скрипт `collect` ходит в MCP сам по персональной ссылке подключения. Работает в Claude Code и терминале.

Дальше конвейер одинаковый:

```text
предполётка → сбор (raw/) → normalize → dataset.json → [metrika.json] → diagnose → findings.json
           → гейт: сводка и вопросы клиенту в чат → render_report → АУДИТ_<slug>.html
```

Рабочие папки — `<папка пользователя>/vk-audits/<slug>-<дата>/`, вне папки скилла; каждый прогон — новая папка.
Пошаговый сценарий для модели, коды выхода и обработка сбоев — в [SKILL.md](SKILL.md).

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest                 # тесты
python -m evals.run_evals        # эталоны
python -m scripts.make_bundle    # архив vk-ads-audit.skill для релиза
```

Версия должна совпадать в `VERSION`, `.claude-plugin/plugin.json` и первом заголовке `CHANGELOG.md` — это проверяет
CI ([version-check](.github/workflows/version-check.yml)), а на тегах `v*` — ещё и с тегом. Без поднятой версии
пользователи плагина изменений не получат.
