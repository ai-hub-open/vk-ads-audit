# vk-ads-audit — дизайн

Дата: 2026-10-14. Статус: согласован по частям в чате, ждёт вычитки.
Методика диагностики — **черновик**: её заменит методичка Лизы по VK-аудиту (раздел 6).

## 1. Зачем

Маркетологу нужен разбор существующего кабинета VK Рекламы: структура, расход, результат, причины и
кандидаты на чистку. Анализ — ежедневная работа, создание кампаний — эпизодическая. В vk-ads-manager анализ
есть только поверхностный (runbook-сценарии 1, 8, 11). От `yandex-direct-audit` берём идеологию:
только чтение, предполётная проверка, опись → статистика → диагноз → находки с приоритетом → отчёт →
ограничения, числа считает скрипт, пороги — в отдельном файле, эталонные прогоны. Методика своя:
VK работает аудиториями, а не ключами; поисковых запросов, площадок РСЯ и корректировок ставок здесь нет.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Форма | Отдельный скилл `vk-ads-audit`, репозиторий `ai-hub-open/vk-ads-audit`, плагин маркетплейса `ai-hub-open`, Apache-2.0 |
| Методика | Каркас сейчас, правила — черновик; методичка Лизы заменяет `diagnostic-rules.md` и `thresholds.json` без правки кода |
| Источники | MCP `vk-ads` (0.11.0) обязательно; Метрика — необязательный усилитель уже в v1 |
| Сбор данных | Гибрид: путь B (скрипт ходит в MCP по HTTP) основной, путь A (модель) — урезанный фолбек |
| Граница с manager | Весь анализ на чтение — в аудите; manager только пишет. Правка manager — отдельная задача |
| Тестовые данные | Синтетические фикстуры по документации; живой прогон — жёсткое условие релиза |

## 3. Режимы и граница

**Только чтение — гарантия кода.** `mcp_client.py` держит белый список инструментов:
`vk_ads_auth_check`, `vk_ads_account_info`, `vk_ads_accounts_list`, `vk_ads_agency_clients_list`,
`vk_ads_ad_plans_list/get`, `vk_ads_campaigns_list/get`, `vk_ads_ad_groups_list/get`,
`vk_ads_banners_list/get`, `vk_ads_statistics_summary/day`, `vk_ads_remarketing_segments_list`,
`vk_ads_remarketing_pixels_list`, `vk_ads_users_lists_list`, `vk_ads_packages_list`,
`vk_ads_regions_search`, `vk_ads_dictionary_get`. Любой другой вызов отклоняется до сети.
В SKILL.md — тот же запрет для модели на пути A.

| | Глубокий аудит | Быстрый анализ |
|---|---|---|
| Триггеры | «аудит VK», «разбери кабинет VK», «почему дорогой лид в VK», «что отключить в VK» | «как у нас в VK», «сводка VK за вчера», «как прошла неделя», конкретный вопрос |
| Охват | кабинет или выбранные кампании, 30 дней по умолчанию (мин. 14) | вчера + 7 дней до этого, или предмет вопроса |
| Результат | `АУДИТ_<slug>.html` + `findings.json` + ограничения | 5–10 строк в чат, только аномалии |
| Метрика | если подключена | нет |

Быстрый анализ при серьёзной аномалии предлагает глубокий аудит, сам не запускает.
Находки сформулированы как действия; выполняет их пользователь или vk-ads-manager.

**Вне v1:** запись в кабинет, режим ведения (недельный цикл), конкуренты, оценка картинок моделью.

## 4. Устройство

```
SKILL.md                  маршрут, режимы, гейты (ориентир ≤ 400 строк)
VERSION, CHANGELOG.md, LICENSE, README.md, .claude-plugin/plugin.json
references/
  mcp-read-tools.md       инструменты на чтение, поля, единицы, особенности ответов
  diagnostic-rules.md     правила диагностики (черновик → методика)
  thresholds.json         пороги; читает скрипт
  metrika-vk.md           трафик VK в Метрике, склейка по UTM
  limitations.md          чего API не умеет; формулировки для отчёта
  report-template.md      структура отчёта
scripts/
  _console.py, _workspace.py   из vk-ads-manager 0.7.1 (UTF-8 консоли; рабочая папка вне скилла)
  credentials.py          реестр ключей ~/.vk-ads-audit/credentials.json (ссылка подключения)
  mcp_client.py           JSON-RPC по HTTP: initialize, tools/call, белый список, пагинация, повторы
  collect.py              путь B: опись + статистика → raw/, журнал вызовов collect_log.json
  normalize.py            raw/ (+ metrika.json) → dataset.json; единицы приводятся ТОЛЬКО здесь
  diagnose.py             dataset.json + thresholds.json → findings.json
  render_report.py        findings.json + dataset.json → HTML (self-contained, печать A4)
  quick.py                быстрый анализ → короткая сводка (JSON + текст для чата)
  make_bundle.py          архив .skill
tests/                    pytest, сеть закрыта
evals/fixtures/           синтетические кабинеты: raw/ + ожидаемые находки
```

**Рабочая папка:** `<папка пользователя>/vk-audits/<slug>-<YYYY-MM-DD>/` — `_state.json`, `raw/`,
`metrika.json`, `dataset.json`, `findings.json`, `collect_log.json`, `АУДИТ_<slug>.html`.
Пути абсолютные; внутри папки скилла — отказ (`_workspace.py`).

**Поток данных:**

```
предполётка → путь B или A
  B: collect.py ─────────────┐
  A: модель сохраняет ответы ├→ raw/*.json → normalize.py → dataset.json
     MCP в raw/ ─────────────┘                                 │
  Метрика (модель, компактно) → metrika.json ─────────────────┤
                                                               ▼
                 diagnose.py → findings.json → render_report.py → АУДИТ_<slug>.html
```

- Один формат `raw/` для обоих путей: файл на вызов, `<инструмент>__<часть>.json` с аргументами и ответом.
- Путь A собирает меньше: сводки по всем группам, объявления — только у 5 групп с наибольшим расходом.
  Недобранное уходит в ограничения.
- Модель не считает: рассуждает над `findings.json`; каждое число отчёта — из `dataset.json`.
- Склейка с Метрикой: шаблон UTM пакетов VK по умолчанию `utm_campaign={{campaign_id}}`,
  `utm_content={{banner_id}}`. Авторазметка выключена → только уровень «весь трафик VK», пометка в ограничениях.
- Ключ пути B — персональная ссылка подключения к MCP; хранится в реестре, в чате не повторяется, в журналах маскируется.

## 5. Ход работы

**Глубокий аудит**

0. Проверка версии (как в остальных скиллах). Охват: кабинет (`accounts_list`, если их несколько), период,
   целевой CPA/CPL (необязателен; без него пороги относительные — к медиане кабинета, с пометкой).
1. Предполётка (только чтение): `auth_check`, `account_info`; есть ли ссылка и проходит ли пробный вызов
   скриптом → путь B, иначе A; подключена ли Метрика и какой счётчик. Итог — в `_state.json` и коротко в чат.
2. Сбор. Опись: кампании (удалённые — только счётчик), группы с полями (статус, цель, пакет, бюджеты,
   таргетинги, `issues`), объявления (статус, модерация, тексты, ссылки, контент), сегменты, списки, пиксели.
   Статистика: сводка за период по группам и объявлениям, по дням — по группам.
3. Нормализация и проверка здравого смысла: сумма объявлений ≈ сумма группы, CTR ≤ 100 %, расход ≥ 0.
   Не прошла — остановка и сообщение, отчёт не строится.
4. Метрика (если есть): трафик VK за тот же период — визиты, отказы, цели; склейка по UTM.
5. Диагностика → находки. Приоритет: ₽ под риском или ₽ роста × надёжность по объёму данных.
6. Гейт: топ находок в чат (5–10 строк) + «есть контекст, который меняет вывод?» (тест, сезон…).
7. Отчёт: HTML + сводка в чат; действия можно передать в vk-ads-manager.

**Быстрый анализ:** облегчённая предполётка → сбор групп и статистики (вчера и 7 дней до) → `quick.py`
ищет аномалии к прошлым дням и к плану (если известен) → 5–10 строк в чат.

**Ошибки:** 401 — объяснить, где взять новую ссылку/токен, дальше не идти; лимит запросов — повторы
с паузой; частичный сбой — продолжать, пропуск в ограничения; нет расхода за период — сказать сразу,
предложить другой период, пустой отчёт не делать.

## 6. Диагностика (черновик)

Находка: `rule_id · уровень · объект · доказательство (числа из dataset) · эффект ₽ · надёжность · действие`.
Уровни: 🔴 срезать слив · 🟠 починить · 🟢 масштабировать · ⚪ гигиена.

| Блок | Правила |
|---|---|
| Структура и гигиена | группа без активных объявлений; отклонённые на модерации (+ `user_can_request_remoderation`); зависшие в ОРД без ERID; `issues` групп (`NO_MONEY`, `AD_PLAN_STOPPED`…); риск автоудаления (нет показов 150+ из 180 дней); 1 объявление в группе или слишком много; бюджет ниже минимума (300 ₽) или мал для обучения; одинаковые таргетинги активных групп; неиспользуемые сегменты и списки; цель «конверсии» без пикселя |
| Эффективность | расход без конверсий ≥ k × целевой CPA; CPA > цели × 1,5 при достаточном объёме; низкий CTR при ≥ 5000 показов; выгорание (CTR падает, частота = показы / охват растёт); oCPM-группы с малым числом конверсий в неделю; концентрация расхода в одной группе; лидер с CPA ниже цели, упирающийся в бюджет → 🟢 |
| Метрика | высокий отказ по группе/объявлению; клики VK ≫ визиты Метрики; цели в Метрике есть, а конверсий в VK нет |

Числа порогов — в `thresholds.json` с источником каждого. Методичка переписывает этот раздел, `diagnostic-rules.md`
и `thresholds.json`; новые типы правил — новые функции в `diagnose.py` по тому же контракту находки.

**Ограничения в каждом отчёте:** нет разрезов (соцдем, гео, площадки, устройства); API не показывает,
срабатывает ли пиксель; атрибуция post-click/post-view меняет число конверсий; сегодняшние данные неполные —
период заканчивается вчера; статусы ОРД видны частично. Плюс недобранное в этом прогоне: путь A, нет Метрики,
нет UTM, частичные сбои.

## 7. Тесты и релиз

**pytest (сеть закрыта):** `mcp_client` — каждый инструмент записи из MCP отклоняется без сети, пагинация,
повторы; `normalize` — единицы, проверка здравого смысла останавливает; `diagnose` — на каждое правило случай
«срабатывает» и «не срабатывает»; `render_report` — числа в HTML совпадают с `dataset.json`; рабочая папка вне скилла.

**evals:** 4 синтетических кабинета (здоровый, слив, гигиена, пустой) с ожидаемыми наборами находок;
детерминированный прогон `raw/ → findings.json` без модели.

**Жёсткие условия релиза 0.1.0:**
1. Прогон на реальном кабинете с расходом ≥ 30 дней, путями B и A, в Claude Desktop.
2. 3–5 чисел отчёта сверены с интерфейсом ads.vk.ru.
3. `collect_log.json` — только вызовы из белого списка.
4. Реальные ответы обезличены и добавлены в фикстуры; разошедшиеся с ними синтетические тесты переписаны.

**Этапы:** (1) каркас, `mcp_client`, `collect`, `normalize` на синтетике → (2) диагностика по черновику
и отчёт → (3) быстрый анализ → (4) Метрика → (5) живой прогон и релиз 0.1.0. Методика — в любой момент после (2).

**Выпуск:** `VERSION` + `plugin.json` + верхняя запись `CHANGELOG` + CI-проверка версии + архив `.skill`.

**Отдельные задачи (вне репозитория):** запись в маркетплейсе `ai-hub-open`; триггеры и сценарии 1, 11
в vk-ads-manager; задачи по MCP у Кузнецова (регистрация ссылок, доступные кабинету пакеты).

## 8. Открытые вопросы (не блокируют этап 1)

- Формат ответов статистики на реальном кабинете (где конверсии, единицы денег) — проверяется живым прогоном;
  до него — по `vk-ads-mcp-integration.md` из manager.
- Сколько `ids` принимает один вызов статистики — подбирается в `collect.py` с запасом, уточняется вживую.
- Пускает ли песочница Claude Desktop исходящие запросы к `vkads-mcp.aihub.click.ru` — проверяется в предполётке.
