# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/): до 1.0 состав правил может меняться.

## 0.1.1 — 2026-10-29

**Прямой отказ на просьбу изменить кабинет** (aihub-639). Скилл только читает, но правила, что
ответить на «поставь на паузу», «удали», «запусти», не было — только «передай в vk-ads-manager».

- **`SKILL.md`, в начале:** ответ одним сообщением — первой фразой «Нет, я только читаю кабинет
  и не могу …», где это сделать (пауза, правка, создание — агент запуска VK после «ОК» или сам
  пользователь в ads.vk.ru; удаление и запуск — только в кабинете), что можешь вместо — и стоп.
  Инструмента нет или вызов отклонён (`forbidden`, `not allowed`, `permission`, `403`) — не сбой:
  без повтора и обхода, строка в ограничения отчёта.
- **«Стиль»:** новая просьба важнее плана. **«Возобновление»:** только по просьбе продолжить.

## 0.1.0 — 2026-10-19

Первая версия: глубокий аудит и быстрый анализ кабинета VK Рекламы только на чтение.
Правила диагностики — черновик до методички.

Исправления по первому живому прогону (16.10.2026):

- Поля: `utm` и `ord_marker` вместо отвергаемых сервером `auto_utm`, `erid`, `ord_token`, `ord_erid`.
- Итоги периода — сумма `statistics_day` (у групп и объявлений): `statistics_summary` — только за всё время, даты не передавать. Охват и частота —
  только у групп, созданных внутри периода, иначе «не определены» (выгорание молчит). `summary_vs_daily` больше не останавливает аудит.
- CTR и CR у VK — уже проценты; бюджеты групп и кампаний — рубли.
- Путь A для больших ответов: `python -m scripts.raw_store import --from <файл>`.
- SKILL.md: в claude.ai и Claude Desktop у коннектора нет персональной ссылки — всегда путь A, ссылку не спрашивать.
- Предполётка расхода: нулевой расход за период — сбор не начинается (путь B — код выхода 5).
- Глубина истории ~366 дней: понятное сообщение вместо сырой ошибки `WRONG_DATE`.
- Нет прав на базы клиентов (429 с лимитом 0): без повторов, строка в ограничениях, C14 — «не проверено: нет прав».
- Сегменты без `size` и `relations`: строка в ограничениях, C13 и C14 — «нет данных».
- Живые формы: `call_to_action: null` — E7 «unknown»; роли контента без соотношения сторон — E1 «unknown», не ❌;
  архивные группы (`ARCHIVED`) не считаются живыми.
- После независимого ревью: сводка (всё время) не подменяет итоги группы или объявления, если дневные вызовы были;
  F3 — «unknown», пока у группы с достаточными показами частота не определена; E5 не ❌ при ролях без соотношения сторон;
  объявления архивных и удалённых групп не попадают в правила и чек-лист; `raw_store import` отказывает на ошибках,
  уже обёрнутых файлах и списках без `items`, предупреждает об одной странице списка; нечитаемый ответ предполётки —
  не «0 ₽»; группа с шаблоном `utm` считается размеченной; сбои предполётки не идут в ограничения.

Исправления по второму живому прогону (16.10.2026, кабинет без живых групп — все 56 удалены):

- Нет активных групп или объявлений — пункты чек-листа A–G «— нечего проверять: нет активных групп» / «…нет активных
  объявлений» вместо ложных «поле не получено», «таргетинги не получены», «статистика не собрана»; гейт «нечего
  проверять» не прячет сработавшую находку. Без живых групп общий балл не считается — «кабинет не откручивает»;
  B7 — только живые группы и их кампании; F5 — «нечего проверять»; C14 и `stale_list` — без активных групп база ни в
  чьём таргетинге; E1 не ругается на группу без активных объявлений (это E3); в «Ограничениях» нет ложных «объявления
  не собирались» и «статистика не собрана».
- `unused_segments` — одна сводная находка «N сегментов не используются ни в одной живой группе» (сколько из них стояли
  только в удалённых или архивных группах, первые id) вместо карточки на каждый сегмент.
- Нулевой расход: предполётка (оба пути) останавливает сбор при 0 ₽, только если живых групп нет; расход кабинета
  из предполётки — `preflight_spent` в `collect_log.json` (путь B) или файл `entity=users` в `raw/` (путь A). Нет живых
  групп и расхода нет — `normalize` останавливается с кодом 5 (SKILL.md говорит, что сказать пользователю; статистика по
  архивным не получена — код 3 «статистика не получена»). Живые группы есть, а их расход 0 ₽ — отчёт с плашкой: «Расход
  кабинета за период 0 ₽» только при подтверждении предполёткой, иначе «Живые группы за период не откручивали; X ₽
  пришлось на удалённые группы» или «Расход живых групп за период 0 ₽». F6, F3 — «нечего проверять», F5 — «у активных групп нет показов за период» (статистики нет — «не собрана»);
  «на удалённые группы» — только если они есть и статистика полная, иначе нейтрально. Быстрый анализ при подтверждённом
  0 ₽ — «Кабинет за период не откручивал (0 ₽)», а не «статистика ещё не пришла».
- «Ограничения»: сбой, после которого тот же вызов (инструмент и аргументы) прошёл — позже в журнале или файлом в
  `raw/`, — не показывается (`mark_recovered`). Ответ-ошибка (`isError`, `error: true`) в `raw/` — не удачный вызов:
  `raw_store check` и нормализация его отвергают.
- `metrics`: `base` у `statistics_day`, `base,uniques` у сводки (вместо `all`); без `uniques` охват — «нет данных», не 0.
- `vk_ads_statistics_summary` вызывается без дат: она только за всё время, с датами MCP отказывает. Охват и частота
  по-прежнему годны лишь для групп, чья жизнь целиком в периоде.
- `autobidding_mode: second_price_mean` — ручная ставка (`manual_bidding_modes`), не автостратегия: правила
  автостратегии и `cap_too_early` её не судят, новой находки на старте нет; в отчёте режим «ручная ставка» /
  «автостратегия» (`bidding_mode_labels`).
- Объявления: собираем `or_status` (статус ОРД) рядом с `ord_marker` — в отчёте справочно («Статус в ОРД»), на A2 не
  влияет.
- Чек-лист: F3 судит те же группы, что правило (и паузные), подходящих нет — «нечего проверять»; Senler без активных
  объявлений — «нечего проверять», не собирались — «нет данных»; B3 у паузных групп без слоёв — «нет данных»; без живых
  групп при расходе архивных — «нет живых групп — общий балл не считается»; падежи («1 группа», «для 1 группы»).
- Авто-UTM: нет ключа `enable_utm` и шаблона `utm` — «не подтверждено» (`None`), а не «выключено»: `utm_missing` по таким
  группам молчит, A3 — «нет данных», в «Ограничениях» — «Авто-UTM у N групп не подтверждена API — проверьте в кабинете»;
  `utm_` в ссылке — метки есть.

Исправления по живому прогону на большом кабинете (16.10.2026, третий прогон: больше сотни групп, MCP 0.12.0):

- Группа в остановленной кампании (кампания `blocked` / `deleted` или issue `AD_PLAN_STOPPED`) — «на паузе (кампания
  остановлена)», а не активная: единый помощник `features.is_active_group` для гейтов чек-листа, лидеров, дублей
  таргетингов C12, D4 и быстрого анализа. Решение методиста: `AD_PLAN_STOPPED` убран из `blocking_issue_codes`.
- Лидер, чей бюджет урезали после конца периода (`updated` группы или кампании позже `date_to`, бюджет меньше среднего
  дневного расхода), — не «+50 %» и не «упирается в бюджет», а ⚪ `leader_budget_changed` «Бюджет менялся после
  периода: сейчас X ₽ при расходе Y ₽ в день — проверьте актуальность». Отчёт предупреждает: «Кабинет менялся после
  конца периода: статусы и бюджеты показаны на дату сбора».
- Слои по `relations` сегментов: пиксель (`remarketing_counter`) и база (`users_list`) — тёплый, ключевые фразы
  (`remarketing_search_phrases`) — холодный; без связей — прежняя логика с пометкой «по догадке»: B1.retargeting не ✅,
  B2–B4 — «нет данных», карточки слоёв — низкой надёжности.
- Объявления по выборке (путь A, топ-5 групп): A2, A3, E1–E9 — «проверено N объявлений в M группах из K активных,
  нарушений нет»; найденное нарушение — ❌.
- E4: недавно редактированное объявление — «дата смены креатива не видна», не «старый креатив»; находка — по честно
  старым.
- Конверсии — «Результат» VK (`base.vk.result`) для всех целей, CPA = расход / результат; `base.goals` — справочно
  («все цели пикселя»). В шапке отчёта — из какого показателя взяты конверсии. Эталоны evals обновлены.
- Чек-лист: сработавшая находка всегда ❌ — гейт «нет данных» / «нечего проверять» заменяет только ✅ (E4 и E6
  показывались «нет данных» при находках); условная карточка (`tentative`) ❌ не ставит.
- Ключевые фразы через сегменты: C6 ✅ «используются (через сегменты ключевых фраз)», C7–C9 — «параметры фраз хранятся в
  сегменте, MCP их не отдаёт».
- Кнопка объявления — из `textblocks.cta_sites_full.text`, когда `call_to_action` пуст; `learnMore` и `visitSite`
  («Перейти на сайт») добавлены в `generic_cta`, `order` («Заказать») — нет (решение методиста 19.10.2026).
- C5 «Пользовательские аудитории» (решение методиста 19.10.2026): в зачёт идут только сегменты пикселя, базы и LAL;
  сегменты ключевых фраз — нет (их судят C6–C9); сегменты неизвестного типа без других — «нет данных».
- Решения методиста 19.10.2026 без изменений в коде: плашка «Бюджет менялся после периода» — без допуска (любое
  изменение); ручная ставка (`second_price_mean`) в первые 7 дней — без находки.
- C13: LAL-сегменты не используются в живых группах — «нечего проверять».
- Охват 0 при показах — «нет данных»; частота — только показы / охват (`uniques.frequency`, `total`, `increment` не
  берём); F3 — «VK не отдаёт охват за период».
- Отчёт по-русски: статус ОРД «активен; коды: превышен дневной лимит», коды VK — словарём (`ISSUE_LABELS`, незнакомый —
  «другая причина (КОД)»), доказательства — с русскими подписями, без `None`, ₽ и %; статус групп в «Структуре»;
  «Не удалось получить список пикселей: ошибка VK 504 (upstream_timeout)» вместо имени инструмента и JSON.
- Сбор: сегменты с `fields=…,relations,relations_count,…` (сервер отверг — повтор без `fields`); «нет доступа к базам» —
  `code: zero_quota` при любом HTTP-статусе (MCP 0.12.0 — 403).
- После независимого ревью: правило 7 дней (решение 5) — и в F6, лидерах, G1–G3 и медиане опорного CPA; объявление в
  правила эффективности — по дням показов в периоде; опорный CPA, F6 и лидеры — внутри одной цели, при нескольких целях
  шапка и плитка конверсий это говорят; находка по группе на паузе — «Группа сейчас на паузе.»; E8, E9, A2, A3 — выборка
  по живым группам; E2, E5 — найдено в выборке — ✅; C7–C9 «нет данных» вслед за C6; E4 — нижняя оценка возраста
  «не менее N дней» и «нет данных» при любой недавней правке; отсутствие LAL — отдельно от слоёв по догадке; фолбэк на
  все цели пикселя честно назван в шапке; тексты для клиента без внутренних терминов.
